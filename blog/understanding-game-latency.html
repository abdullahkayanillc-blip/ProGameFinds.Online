What Causes Game Input Latency? From Button Press to Screen

“Lag” is often used for several different problems. A slow response between a button press and the screen is not the same as a high multiplayer ping. Separating the stages makes troubleshooting more precise.

ProGameFinds Editorial TeamPublished 28 November 20268 min read
Main idea: System latency is the time from a physical input to the resulting image on the display. Network latency is the time for information to travel between the game client and a server. They can happen together, but they are not the same measurement.

One action passes through several stages

When a player presses a button or moves a mouse, the input device detects the action and sends an event to the connected system. The game reads that event, updates its simulation, prepares a frame, sends rendering work to the graphics processor and eventually presents an image on the display. Each stage takes time and may add delay.

NVIDIA describes a set of broad stages: peripheral latency, game latency, render latency and display latency. Together they form a useful model for understanding click-to-display or end-to-end system latency. The exact pipeline varies by device, operating system, game engine and graphics configuration.

Peripheral latency: the device and its connection

The controller, mouse or keyboard has to detect an action and report it to the computer or console. The device's electronics, firmware and connection method affect this stage. Polling rate describes how often a device reports its state, but it is not a complete measure of end-to-end responsiveness. A higher polling number cannot remove delays later in the game or display pipeline.

Button travel, switch behaviour and the device's internal processing can also contribute. When comparing two peripherals, keep the game, display and settings constant. Otherwise, it is difficult to attribute a visible difference to the input device itself.

Game and CPU processing

After an input arrives, the game has to process it. The CPU may update player state, physics, animation, audio and other simulation tasks before submitting graphics work. A CPU-bound game may take longer to prepare each frame, even when the graphics processor is not fully occupied.

Frame pacing also matters. A game that produces frames at uneven intervals can feel less consistent than one with stable frame times, even if their average frame rates look similar. Microsoft's Xbox Game Development Kit includes a frame-pacing sample that demonstrates how CPU work, GPU work, buffers and scheduling interact. It is a development example, not a universal benchmark for every game.

Render queues and the GPU

The GPU renders the work submitted by the game. If the CPU submits frames ahead of the GPU, some work may wait in a render queue. Queues help keep the GPU supplied with work, but waiting frames can add time between an input and the image that reflects it.

Graphics settings can affect this balance. A demanding setting may increase GPU render time; an overloaded system may also produce frame-time spikes. Reducing visual settings can sometimes help when the GPU is the bottleneck, but it is not a universal fix for every latency problem. Measure the same scene before and after changing a setting.

Some technologies are designed to coordinate CPU and GPU work more closely. NVIDIA Reflex is one example that developers can integrate into supported games. Its availability and effect depend on the specific game, hardware and configuration. It does not remove every source of system or network delay.

Display latency: the last part of the chain

After the GPU completes a frame, the display still has to present it. Display processing, refresh timing and the way a monitor handles incoming frames can affect when the result becomes visible. A monitor's advertised refresh rate tells you how frequently it can refresh under supported conditions; it does not describe every part of its signal processing or total system latency.

For a fair comparison, verify that the monitor is actually running at the intended resolution and refresh mode. Check the input selected, relevant image-processing settings and the connection path. Manufacturer specifications and actual measurement conditions should be kept separate.

Network ping is a different kind of lag

Network latency, often shown as ping, measures the round-trip time between a game client and a server. It can affect hit confirmation, player positions and interactions in online games. Packet loss or jitter may cause additional symptoms such as freezing or inconsistent updates. A low ping does not guarantee low click-to-display system latency, and a responsive local system does not guarantee a low-latency route to a distant server.

A practical troubleshooting sequence

  1. Describe the symptom: slow local response, uneven frame pacing, delayed online actions or network stutter.
  2. Check the input device and connection without changing other variables.
  3. Confirm the game, operating system and display are using the intended performance settings.
  4. Measure frame rate and frame-time consistency in the same repeatable scene.
  5. Check CPU and GPU utilisation to see which part is limiting frame production.
  6. For online symptoms, compare ping stability and packet loss separately from local system responsiveness.

The practical takeaway

There is no single setting or polling-rate label that describes total gaming responsiveness. Follow the signal from the input device through the game, CPU, render queue, GPU and display. Investigate network behaviour separately. A clear diagnosis is more useful than changing every setting at once.
